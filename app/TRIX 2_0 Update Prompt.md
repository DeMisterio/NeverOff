# TRIX 2.0 — Промпт апдейта (5 стадий)

Разбивка построена по логике зависимостей и MoSCoW-приоритету: сначала критичные баги основного экрана, затем визуальные доработки того же экрана, затем анимации/полировка, затем редизайн настроек (зависит от части фиксов этапа 1–3), и в конце — новая инфраструктурная фича (автообновление), не зависящая от остального.

---

## Стадия 1 — Критические фиксы Main Menu (Must Have)

Цель: убрать баги, ломающие базовый UX и функциональность.

- **Локализация**: перевести "Search" в поле типа, "Fav" в получателях, тексты Settings / three-dot options / theme preferences на английский.
- **Отступы**: "+" — 8px margin справа; лупа поиска — пропорциональный отступ слева.
- **Индикатор соединения**: заменить быстрое мигание текста статуса на opacity-wave анимацию (снизу вверх) для "потерянных" элементов при загрузке.
- **Поле ввода**: исправить цвет поля ввода — сейчас совпадает с фоном (wallpaper).
- **Статус отправки**: реализовать real-time индикатор доставки для каждого сообщения + локальное сохранение статуса.
- **Selection & Forwarding (M3)** — реализовать полностью:
  - активация режима выбора: бабблы сдвигаются вправо, слева появляются круглые чекбоксы;
  - выбор тапом по сообщению или чекбоксу;
  - drag-select чекбоксов при скролле (диапазон выделения);
  - forward: иконка изогнутой стрелки → попап в стиле Main Menu со списком контактов (чекбоксы) → pill-кнопка "Forward" рассылает выбранные сообщения по контактам отдельными сообщениями;
  - маленькая иконка forward-стрелки должна отображаться в строке индикатора просмотра/времени у всех пересланных сообщений;
  - удаление диапазона: запрос "удалить у себя / у всех";
  - копирование изображений с сохранением временных/пользовательских меток.

**Критерий готовности:** все M-пункты Main Menu закрыты, приложение проходит smoke-test базового флоу переписки и пересылки.

## Стадия 2 — Доработки бабблов и layout (Should Have)

Цель: привести визуал сообщений и полей ввода в порядок.

- Время/статус доставки переносится на одну строку с текстом сообщения (справа), если помещается по ширине.
- Выровнять внутренние отступы баббла — сделать пропорциональными со всех сторон.
- Адаптивный цвет текста времени/статуса внутри баббла: авто black/white в зависимости от цвета баббла (для всех тем, не только для оппонента).
- Кэширование логотипов/аватаров в локальную БД (сейчас не скачиваются).
- Регулировка яркости wallpaper в настройках темы.
- Оптимизация рендера текста при скролле (устранить рывки/лаги при появлении текста).
- "+" в поле ввода — открыть меню опций (галерея, файлы) с переходом в соответствующий флоу.
- Swipe-to-reply: нелинейная анимация свайпа (чем дальше — тем тяжелее), плавное появление иконки reply слева при сдвиге баббла, лёгкий эффект растяжения при приближении к лимиту.
- Reply-preview панель над полем ввода — фон в цвет текущей темы.
- Reply-баббл внутри сообщения — квадратная (не овальная) форма, с корректными внутренними отступами.

**Критерий готовности:** визуальный QA бабблов и полей ввода на всех темах, включая крайние случаи длины текста.

## Стадия 3 — Анимации и полировка (Could Have + Won't)

Цель: анимационный слой поверх уже стабильного функционала.

- Bubble stretch: при достижении лимита свайпа — баббл "силиконово" сжимается по высоте / растягивается по ширине, при отпускании — bounce back к исходной форме.
- Тени у бабблов.
- Единый стандарт скругления для всех pill/squared элементов приложения.
- Изменение размера шрифта → пропорциональное изменение размера баббла.
- Аватар в профиле пользователя:
  - изначально круг (~2см) по центру сверху;
  - при скролле вниз — плавная трансформация в квадрат на всю ширину сверху;
  - при дальнейшем скролле — зум с увеличением высоты (остальные элементы уезжают вниз);
  - при достижении лимита (+30% высоты) — плавный переход в центр экрана и открытие полноэкранного вьювера.
- Убрать нижнюю кнопку Settings из профиля — объединить с Edit Profile в одну pill.
- Убрать редактирование цвета баббла из настроек.
- Глобальный "bouncy" эффект для всех кнопок приложения.

**Критерий готовности:** все анимации проходят через единый animation-controller (нужен для Стадии 4, где эти же параметры регулируются в настройках).

## Стадия 4 — Редизайн Settings

Цель: новая архитектура настроек + привязка анимационных/приватность-параметров к UI.

- **Структура**: Settings открывает меню выбора категории (не плоский список).
- **Language**: попап со списком языков, поиск сверху, элементы — pill, выбранный язык — затемнённая pill.
- **Appearance** (бывший theme preferences):
  - переезд в отдельную категорию, открывается как меню (не попап);
  - настройки применяются глобально ко всем чатам;
  - при открытии appearance внутри конкретного чата — пометка "для этого чата";
  - в глобальном меню — пометка "For all chats";
  - смена глобальной темы не затрагивает чаты с независимо настроенной темой, если не отмечен чекбокс "Apply to already changed".
- **Developer settings**: новая категория (иконка "жук"), всегда последним пунктом списка.
- **Appearance → Animations** (pill, one-line, ">" справа):
  - 3 горизонтально скроллящихся превью-окна (крупные, вытянутые по высоте):
    1. бесконечный скролл чата (ускорение от медленного к быстрому, без остановки);
    2. свайп баббла до лимита растяжения + bounce back;
    3. бесконечная отправка/получение сообщений;
  - при открытии одного превью — соседние останавливают анимацию (оптимизация);
  - слайдер "bounciness" — синхронно обновляет параметры и превью;
  - тумблер stretchiness on/off;
  - общий тумблер all animations on/off (наверху);
  - чекбокс "optimise optimisation" — авто-адаптация параметров под железо устройства.
- **Privacy** (новая категория):
  - auto-delete сообщений — слайдер срока хранения по чатам (при включении);
  - тумблер "seen"-индикатора — отдельно для себя и для остальных;
  - управление видимостью описания профиля, аватара и online-статуса (кто может видеть).

**Критерий готовности:** все новые категории настроек связаны с соответствующей логикой Стадий 1–3 (тема/анимации/приватность реально влияют на чаты).

## Стадия 5 — Новая фича: автообновление

Цель: инфраструктура апдейтов без привязки к остальному функционалу.

- Создать в Supabase таблицу `versions` с колонками: `version`, `description`, `google_link`.
- При подключении приложение:
  - парсит таблицу, сравнивает текущую версию с последней серверной;
  - при наличии новой версии — показывает баннер снизу экрана.
- Баннер: возможность скрыть, посмотреть "что нового" (description), кнопка скачать.
- Скачивание apk в фоне через API, статус загрузки отображается в том же баннере (progress).
- По завершении — кнопка "Install" триггерит команду открытия файла в Android (запуск установщика).

**Критерий готовности:** полный цикл проверен на тестовой записи в `versions` — от появления баннера до установки.

---

### Примечание по порядку

Стадии 1→3 должны идти последовательно (каждая опирается на стабильность предыдущей на одном экране). Стадия 4 частично зависит от Стадии 3 (animation-controller). Стадия 5 независима и может разрабатываться параллельно с любой из стадий 1–4.
